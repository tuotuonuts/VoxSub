## 2. 普通诊断

- 默认改为只读快速检查当前配置，不再打开诊断就加载 ASR/VAD/TTS。选中/有效模型文件检查、语言对兼容性、音源/保存录音意图、资源余量、可用 ORT providers 均有明确范围。
- 显示通过、异常、未检查、检查中、资源不足，保留影响与建议；空结果不是「全部 0 项正常」。已知失败不会被其他未检查项目弱化。
- 检测到设备、模型加载、provider 声明与实际执行证据分开；未验证的 GPU/NPU 明确标未验证，不推测。
- 自检缓存绑定模型/语言/模式/音源/录音配置；导出不重跑自检。配置改变后不导出旧正常结论，记录原检查时间及导出时运行快照。
- 日志按级别、关键词、本次应用运行、最新模型会话筛选；暂停滚动不停止采集日志，恢复后可查看新记录。历史读取最多 2 MB，避免 GB 日志一次读入。

## 3. 模型状态追踪

独立 diagnostic_trace 模块保存最多 500 条事件；renderer IPC 指标最多 200 条。包括应用 run_id、模型会话 id、单次请求 id、阶段、模型/运行时标识、语言快照、配置代次、队列等待、耗时、输入/输出长度、错误类型/HTTP 状态或 errno、语言约束疑似不符及 fallback。覆盖最终翻译、实时草稿、识别结果、模型构建、文件翻译及队列过载。

内容由 scalar allowlist 限定；不保存音频、原文、译文、提示词或凭据。语言不符判断是字符/脚本启发式，不是准确的语言检测，短句、专名、混合语言有误判可能。硬件丢帧未测，不能冒报 0；采集帧、暂停省略帧、队列拒绝帧与队列积压分别呈现。

## 4. 导出与日志容量

- 报告与日志导出共用隐私说明/确认，取消不弹保存框、不发送导出。
- 版本、检查时间、范围和脱敏元数据可导出；普通自由文本日志正文默认省略，仅导出经过 allowlist 的 MODEL_TRACE 数据，避免正则无法识别的识别/翻译正文和服务端错误正文泄漏。密钥、URL、敏感路径进一步遮蔽。无音频或历史附件，不自动上传。
- 设置 → 存储与模型 → 日志存储上限，支持 MB/GB（1024 换算），10 MB～10 GB，默认 50 MB，显式保存，降低上限需确认。
- 管理 voxsub.log 与 .1～.9 的总预算；最旧轮转日志淘汰。UTF-8 按字节计量，单条最多 16384 字符。导出报告、其他日志文件、模型、配置和历史不属于此预算，不能删除它们。拒绝活动日志符号链接。文件锁/不可写问题仍需用户处理，不能声称磁盘层强制删除总能成功。

## 5. 开发者模式

设置 → 关于 → **5 秒内点击版本号 10 次** → 确认开启。仅本次应用启动有效，有关闭按钮；不自动开启 DevTools、不录音、不上传、不解除安全保护。隐藏入口不是权限或安全边界，开发者功能只是排障，不提供任意命令执行。

诊断页新增开发者分页：IPC 耗时/超时/近期错误；Pipeline 状态、各队列容量/积压、采集计数、模型加载阶段、声明 provider 与未验证边界、fallback、进程 RSS 和可用内存；5 分钟详细日志、倒计时、结束按钮；复制脱敏快照。

详细日志到期有独立 daemon timer；替换/关闭会话取消旧计时器，旧回调按 session_id 校验所有权，不能停止新会话。结束日志/关闭模式为控制命令，不排在下载/迁移等长作业后面。页面销毁只释放 UI 计时器，不偷偷中断用户的有界日志会话。

环境信息按按钮显式采集，包含 CPU、主板、BIOS、OS 产品/版本/build、驱动设备型号/类别/厂商/版本（最多 256 条）、Python 和已安装推理依赖版本，以及渲染环境。拒绝序列号、用户名、主机名、凭据和正文等识别字段；不联网。环境采集最长 12 秒，失败/超时如实返回，不能宣称枚举总是完整。
