# 实时识别与翻译延迟优化：第一轮验收

## 改动范围

- 原生部分识别结果提供活动句草稿；稳定观察、足够增长或短暂静置后再翻译，按近期推理成本自适应节流。
- 最终句优先；音频、识别或上下文积压时暂缓可选草稿，不通过删除最终句来掩盖延迟。
- 同句、同配置、同翻译器、同上下文且正文完全一致时，短期一次性复用已校验草稿；旧会话、旧句与配置切换隔离。
- 各实时档位可独立开启双语草稿，文件模式不启用。非流式模型不会因此自动变成流式模型。
- 主窗与浮窗共用 subtitle-draft 合并组件，兼容增长/末词修订时保留译文，避免每次原文变化都清空译文。
- 新增有界阶段耗时统计与积压提示；空样本保持未验证。正文缓存只留内存，不进入诊断快照。
- 可选草稿预算为1200ms；OPUS仅在原生调用间检查软期限，无法中断单次ORT调用；Qwen草稿只用已预热服务发单次请求，不为草稿重建服务。客户端超时不代表服务端GPU工作已取消。
- 最后审查修复语言校验拦截终句后未释放pending标记的问题，防止后续草稿一直等待；该路径日志改为字符数。
