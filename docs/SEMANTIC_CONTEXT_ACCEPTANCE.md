# 智能上下文识别/翻译优化验收

## 范围与结论

本轮是源码算法优化，不更新用户配置、历史、已安装模型或安装版，不递增版本、不打包或发布。只在已有智能上下文调优模式启用；自动/响应/均衡/准确/自定义保持旁路。无额外模型，D/OCR 现有批量上下文保持不变。

结论：**有界上下文、纠偏/断句安全与兼容性回归通过；真实翻译质量是短样本有限改善，不是统计质量验收，也不能保证消除所有歧义。** ASR 权重/声学解码器未改，没有真实音频 CER/WER 评估。原有 Granite/Index 上架和单模型集成状态未改变。

## 实现与安全边界

- 新独立 `voxsub/translate/context.py`：最多 3 对近期定稿，每侧不超过 200 字；90 秒过期，明确换话题提示清空。参考只在进程内，不读取历史或导出正文。语言检查通过不代表译文语义必然正确；错误但符合目标语言的译文仍可能影响后续，需更大样本验证。
- 实时上下文按配置代次、语言对和翻译器身份隔离，启动/运行时释放清空；配置切换中的旧结果不能进入新参考。草稿只能读取，不写入参考；失败/空结果不写入；语言拒绝仍在原模型元数据诊断中记录。
- 文件字幕的本地/云识别两条入口都按当前 tuning 接入；参考每个文件任务独享，以字幕时间计算过期，时间倒退清空。保持原字幕文本和时间戳，不强行合并字幕行。文件 ASR 识别/分段本轮未改变。
- 质量与云翻译具备可选 `translate_with_context`，快档回到逐句路径。参考是 user 消息 JSON 数据，不增加 system 角色、不提高输出预算；质量档最多 384 UTF-8 字节、云档最多 1024 字节（含参考说明）。质量档还为原输入/输出保留空间；不是精确 tokenizer 计数或提示注入安全保证。原质量档已有严格重试保留，重试不携带参考；未增加第二模型或新的翻译调用。
- 云参考发往已经显式配置且通过白名单的同一端点，不自动配置云端、不读密钥进上下文。本地不新增历史存储；云服务自己的留存策略不在本地保证范围。
- 断句：短的明确主谓句不再一律等硬截止；强连接/补语词优先于解码器句号；引号闭合、省略号和拖尾逗号/冒号被纳入。首段硬等待不续期，待定文本达到 600 字就提交，不截断原文。仍是中英启发式，不是完整多语语法分析。
- 纠偏：同分重叠候选保留原识别证据；保护精确已有词、数字/中文数量/版本、否定及动作标记；保留 raw_text 和修改记录，词频仅由原始识别建立，不由纠偏结果自强化。词表限 64 热词+64 近期候选，最近每句证据最多 512 字；超长输入跳过纠偏。只能有限等长替换，不做字符重排；用提前退出的线性替换距离代替每个窗口的二次编辑距离。
- 轻度填充词处理保留“额外”“呃逆”的词首；不删除可能表示否定的“唔”。无分隔符的前缀清理只保留“嗯”；仍可由已有设置关闭。

## 真实文本对照（最终复验）

| 前文 | 当前句 | 逐句译文 | 有界上下文译文 | 结论 |
|---|---|---|---|---|
| We walked along the river bank. | The bank was damaged. | 银行受到了损坏。 | 银行受到了损坏。 | 未消歧（已知限制） |
| The river flooded yesterday. | Its bank was damaged. | 它的银行受到了损坏。 | 其河岸受到了破坏。 | 观察到消歧改善 |
| She is a baseball player. | She picked up the bat. | 她拿起了球棒。 | 她拿起球棒。 | 两者基本正确 |
| The server is running on the local network. | The port is not open. | 端口未开放。 | 端口未开放。 | 否定/网络语义保持 |

附带参考会增加输入开销。最终本机 CPU 短句逐句约 0.37～0.66 秒，上下文约 1.02～1.54 秒（不含冷启动或前句翻译）。模型原采样参数没有为验收特意改成确定性；只说明这些实际输出，不宣称统计因果增益。两次有代词的 river/bank 对照均观察到“银行→河岸”；无代词那句仍不能消歧，保留失败样本。
